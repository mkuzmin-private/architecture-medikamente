### Задание 2
1. Отсутствуют механизмы разграничения доступа к данным пациентов среди сотрудников компании: сотрудники могут редактировать/удалять данные пациентов. Высокий риск утечки и повреждений данных.
2. Данные хранятся в открытом виде (нет шифрования, маскирования, обфускации). В случае утечки все персональные данные (ФИО, адрес, дата рождения, телефон, сканы документов), пациентов будут доступны злоумышленникам. Сотрудники IT-отдела при составлении отчетов также работают с открытыми данными.
3. Все действия, совершаемые сотрудниками с данными компании никак не логируются.
4. Нет информации о регулярном сохранении резервных копий данных. В случае удаления файлов (возможно даже непреднамеренного) данные будут утеряны.
5. Кроме доменной аутентификации, со стороны систем обработки нет ограничений на доступ к данным.
6. Если пациент обратится в компанию с просьбой удалить все его персональные данные, то у компании нет такого инструмента, что является нарушением ФЗ-152.
7. Пользователю предлагается заполнять расширенную форму с адресами учебы/работы, адреса прописки. При этом непонятно как и кем используется эта информация.
8. Персональные данные пациентов никак не тегируются/классифицируются. Нет какой-либо платформы управления данными.

### Задание 3
1. Провести оценку данных. Чтобы понять, какие данные действительно необходимы, нужно провести анализ и классификацию всех обрабатываемых и хранимых данных. Присвоить метки всем чувствительным данным (PII, PHI, MED, FIN, ...). Также добавить теги для этапов обработки данных (например, raw_lab_results, verified_lab_results, lab_analytics)
2. Установить сроки хранения данных и реализовать их уничтожение после окончания срока хранения.
3. Вместо Excel файлов предусмотреть использование персистентных СУБД. Все персональные данные необходимо хранить только в зашифрованном виде, чтобы в случае утечки злоумышленник не мог ими воспользоваться.
4. Ввести механизмы защиты данных - обфускация, шифрование и маскирование. Пользователи с разными ролями должны видеть в открытом виде только те данные, которые им действительно нужно для выполнения процесса.
5. Необходимо четко разграничить права доступа к различным данным. Для этого нужно ввести RBAC/ABAC правила доступа для ролей в системе (Доктор, Ресепшен, Пациент, ...). Здесь предусмотреть интеграцию с тегами, чтобы определять соответствует ли роль пользователя уровню доступа, заданному тегами данных.
6. Ввести аудит и логирование всех действий пользователей. Предусмотреть логирование исходящих и входящих запросов к внешним системам (например, в лабораторию). Перс. данные в логах также должны маскироваться. 
7. Предусмотреть механизмы регулярных бэков для предотвращения утери данных в случае аварий.
